# postmarketOS + Phosh на mainline-ядре для Samsung Galaxy M52 5G (m52xq): пошаговая инструкция

Сборка образа корня postmarketOS edge (systemd) с оболочкой Phosh для нашего ядра 7.1.13 #444, без Halium и Android.
Это пошаговая инструкция с командами: по ней сборку может повторить любой. Каждая выполненная команда записывается сюда
вместе с результатом. Папка проекта на нашем компьютере: `~/Templates/майнлайн/дроидиан/постмаркет/`.

Текущее состояние смотрите в разделе «Журнал» в конце.

## 0. Что получаем и зачем

- Система: **postmarketOS edge** (Alpine edge + pmaports main), init — **systemd** (канал `systemd-edge`).
  В `/etc/os-release` она называется `PRETTY_NAME="Nura edge"`.
- Оболочка: **Phosh 0.58** (композитор phoc 0.58, клавиатура stevia 0.58), стандартный набор приложений `postmarketos-ui-phosh`.
- Железо: наш пакет устройства `device-samsung-m52xq` r7 и модули ядра **7.1.13 #444**, того же ядра, что у порта Ubuntu Lomiri.
  Ядро ставится отдельно, как `boot.img`. Пакет `linux-samsung-m52xq` в образе — только заглушка.
- Результат: `samsung-m52xq-root.img` (ext4, метка `pmOS_root`) и `samsung-m52xq-boot.img` (pmbootstrap `--split`).
- Сборка идёт в **отдельном рабочем каталоге** pmbootstrap. Рабочие каталоги портов Plasma и Lomiri она не трогает.

На этом этапе в образе нет правок m52xq из портов Plasma и Lomiri: звука, модема с DSDS, сна Wi-Fi, камеры, служб `m52xq-*`.
Их переносим по одной и каждую проверяем на телефоне.

## 1. Что нужно на компьютере

Наш хост: Ubuntu 20.04 x86_64 (ядро 5.15). Нужны sudo, около 10 ГБ свободного места и интернет.

```sh
# Python 3.10 (pmbootstrap 3.11 не работает на системном 3.8 из Ubuntu 20.04); у нас собран в /opt/python3.10
/opt/python3.10/bin/python3.10 --version          # Python 3.10.14
# pmbootstrap 3.11.1 из исходников
PMB_DIR=~/Templates/майнлайн/tools/pmbootstrap
/opt/python3.10/bin/python3.10 $PMB_DIR/pmbootstrap.py --version     # 3.11.1
git --version                                     # 2.25.1 (старый: у git init нет ключа -b)
```

Запуск arm64-программ: pmbootstrap сам ставит `qemu-aarch64` в native-chroot и регистрирует binfmt на время работы.
Ставить на хост `qemu-user-static` не нужно.

Сокращение, которое используется ниже:

```sh
D=~/Templates/майнлайн/дроидиан/постмаркет            # папка проекта
W=$D/work                                             # отдельный рабочий каталог pmbootstrap
O=~/.local/var/pmbootstrap                            # основной рабочий каталог (порт Plasma), из него берём только ключ подписи и version
PB="/opt/python3.10/bin/python3.10 $PMB_DIR/pmbootstrap.py -c $D/pmbootstrap-phosh.cfg"
```

## 2. pmaports и пакет устройства

pmaports: `https://gitlab.postmarketos.org/postmarketOS/pmaports.git`, ветка `main`. У нас это коммит
`cc0c3e1` (2026-10-02) с локальными правками, поэтому pmbootstrap пишет «pmaports: main, dirty».

```sh
cd ~/.local/var/pmbootstrap/cache_git/pmaports
git remote -v | head -1; git log -1 --format='%h %cd'
# пакет устройства из этого репозитория -> device/testing/
cp -a <репо>/device-pkg/device-samsung-m52xq device/testing/
```

`device-pkg/device-samsung-m52xq` содержит:
- `deviceinfo`: `deviceinfo_dtb="qcom/sm7325-samsung-m52xq"`, `deviceinfo_flash_method="none"`,
  `deviceinfo_rootfs_image_sector_size="4096"` (UFS телефона с секторами 4096 байт; без этого `losetup -P` в initramfs считает
  смещения разделов неверно);
- `APKBUILD` r7. В `package()` есть две ссылки-заплатки для Go-версии mkinitfs: `/etc/deviceinfo!optional` и
  `/usr/lib/libsystemd-shared-262.so`;
- `device-samsung-m52xq.post-install` (`post-upgrade` — ссылка на него). Симлинк `/usr/bin/losetup` создаётся, только если файла
  нет и `/usr/sbin` — отдельный каталог. Почему так — см. раздел 9, ловушка 1.

Пересборка пакета устройства (несколько секунд, кросс-сборка через crossdirect):

```sh
$PB build --arch aarch64 device-samsung-m52xq
# => edge/device-samsung-m52xq: Done!   ->  $W/packages/edge/aarch64/device-samsung-m52xq-1-r7.apk (3563 байт)
```

**Всегда указывайте `--arch aarch64`.** Без этого ключа pmbootstrap собирает пакет под архитектуру хоста.

Пакет ядра `linux-samsung-m52xq-7.1.2-r1` — заглушка, собранная 2026-09-13. В ней лежат `boot/vmlinuz-samsung-m52xq` и
`usr/share/kernel/samsung-m52xq/kernel.release`, оба с текстом `dummy`. Она нужна только для зависимости пакета устройства,
поэтому mkinitfs пишет «Generating for kernel version: dummy». Оба пакета лежат в `image/local-repo/`, суммы в `SHA256SUMS`;
подписаны ключом `pmos@local-6aa7025b.rsa.pub`, он лежит там же.

## 3. Отдельный рабочий каталог

```sh
mkdir -p $W/packages/edge/aarch64 $W/config_apk_keys $W/config_abuild
cp $O/version $W/                                                    # формат рабочего каталога: 8
cp <репо>/image/local-repo/*.apk $W/packages/edge/aarch64/
cp $O/config_apk_keys/pmos@local-6aa7025b.rsa.pub $W/config_apk_keys/
sudo cp -a $O/config_abuild/. $W/config_abuild/                      # закрытый ключ подписи: читается только через sudo
sudo chown -R 12345:12345 $W/config_abuild $W/packages               # uid 12345 = пользователь pmos внутри chroot
```

Конфиг `$D/pmbootstrap-phosh.cfg` (копия: `image/pmbootstrap-phosh.cfg`):

```ini
[pmbootstrap]
aports = ~/.local/var/pmbootstrap/cache_git/pmaports
work = ~/Templates/майнлайн/дроидиан/постмаркет/work
device = samsung-m52xq
ui = phosh
ui_extras = False
hostname = samsung-m52xq
timezone = Etc/UTC
build_pkgs_on_install = False
is_default_channel = False
auto_zap_misconfigured_chroots = yes
extra_packages = none
```

В конфиге pmbootstrap пишите полные пути, `~` здесь только для краткости.
`build_pkgs_on_install = False` нужен затем, чтобы pmbootstrap не начал сам собирать пакеты из локальных правок `temp/`
(libcamera, megapixels и др.) при установке.

Проверка:

```sh
$PB config ui      # phosh
$PB config work    # .../постмаркет/work
```

## 4. Индекс локального репозитория

```sh
$PB index
# Channel: systemd-edge (pmaports: main, dirty) / UI: phosh / systemd: yes ... DONE!
ls $W/packages/edge/aarch64        # APKINDEX.tar.gz + два .apk
```

Если папка `packages` принадлежит пользователю хоста, команда падает:
`Can't open ".SIGN.RSA.pmos@local-6aa7025b.rsa.pub" for writing, Permission denied`. Исправление — `chown` из раздела 3.

## 5. Установка в образ

```sh
cd $D
$PB -y install --password 1111 --split > install.log 2>&1; echo EXIT=$?
```

Шаги (около 7 минут):
1. `(1/4) PREPARE NATIVE CHROOT`: cryptsetup, util-linux, parted;
2. `(2/4) CREATE DEVICE ROOTFS`: qemu-aarch64, `postmarketos-base-systemd`, затем `postmarketos-ui-phosh` и набор
   приложений (1072 пакета, всего в образе 1184);
3. пользователь `user` с паролем 1111, `/etc/fstab`, `mkinitfs`;
4. `(4/4) FILL INSTALL BLOCKDEVICE`: копия корня в образ.

```
SSH daemon is enabled (disable with --no-sshd).
Firewall is enabled, but may not work (couldn't determine if kernel supports nftables).
DONE!
```

Ошибка mkinitfs с `EvalSymlinks: too many links` для `/usr/sbin/losetup` — это раздел 9, ловушка 1.
Если она уже случилась (стоял пакет устройства r6), почините в собираемом корне и запустите `install` ещё раз:

```sh
$PB chroot -r -- apk fix losetup      # OK: 1811.4 MiB in 1184 packages
ls -la $W/chroot_rootfs_samsung-m52xq/usr/bin/losetup      # обычный файл 67688 байт
$PB -y install --password 1111 --split > install2.log 2>&1; echo EXIT=$?     # EXIT=0
```

Забираем образы и останавливаем chroot:

```sh
$PB shutdown
cp $W/chroot_native/home/pmos/rootfs/samsung-m52xq-root.img $W/chroot_native/home/pmos/rootfs/samsung-m52xq-boot.img $D/
```

## 6. Модули ядра 7.1.13 #444

Модули берём из архива модулей релиза `kernel-7.1.13` (samsung-m52xq-ubuntu-lomiri) или из `003/в6/rootfs-files/lib/modules/7.1.13`.
Там 23 файла `.ko`, список в `kernel/modules-7.1.13-444.txt`. В edge объединённый `/usr`, `lib -> usr/lib`, поэтому модули кладём
в `/usr/lib/modules`.

```sh
MODULES=/путь/к/lib/modules/7.1.13
mkdir -p $D/mnt; sudo mount -o loop $D/samsung-m52xq-root.img $D/mnt
sudo mkdir -p $D/mnt/usr/lib/modules
sudo cp -a $MODULES $D/mnt/usr/lib/modules/
sudo chown -R 0:0 $D/mnt/usr/lib/modules/7.1.13
sudo depmod -b $D/mnt 7.1.13
# kmod хоста старый и печатает "kmod_builtin_iter_next: unexpected string without modname prefix" — modules.dep всё равно пишется
wc -l < $D/mnt/usr/lib/modules/7.1.13/modules.dep     # 18
df -h $D/mnt | tail -1                                 # 2.2G, занято 1.9G, свободно 155M
sudo umount $D/mnt; rmdir $D/mnt
```

## 7. Проверка образа

e2fsck хоста (1.45.5) не знает флаг `orphan_file`, который ставит mke2fs 1.47. Он пишет
`unsupported feature(s): FEATURE_C12` и «Файловая система всё ещё содержит ошибки», но это ложная тревога.
Проверяем новым e2fsck из native-chroot Alpine; образ даём через жёсткую ссылку, а не копию:

```sh
R=$W/chroot_native/home/pmos/rootfs
sudo mv $R/samsung-m52xq-root.img $R/orig-root.img
sudo ln $D/samsung-m52xq-root.img $R/samsung-m52xq-root.img
$PB chroot -- sh -c 'apk add -q e2fsprogs; e2fsck -V; e2fsck -fn /home/pmos/rootfs/samsung-m52xq-root.img; echo rc=$?'
# e2fsck 1.47.4 ... pmOS_root: 32321/300960 files (0.1% non-contiguous), 527738/601344 blocks   rc=0
sudo rm $R/samsung-m52xq-root.img; sudo mv $R/orig-root.img $R/samsung-m52xq-root.img
$PB shutdown
```

Содержимое (только чтение):

```sh
mkdir -p $D/mnt; sudo mount -o loop,ro $D/samsung-m52xq-root.img $D/mnt
grep PRETTY $D/mnt/etc/os-release                   # PRETTY_NAME="Nura edge"
ls -la $D/mnt/usr/bin/losetup                       # обычный файл 67688 байт, не ссылка
ls $D/mnt/usr/lib/modules/                          # 7.1.13
ls $D/mnt/usr/share/wayland-sessions/               # phosh.desktop
sudo ls $D/mnt/etc/systemd/system/multi-user.target.wants/
# ModemManager NetworkManager sshd tuned unudhcpd@usb0 wpa_supplicant avahi-daemon cups.path rtkit-daemon systemd-oomd ...
grep ^user: $D/mnt/etc/passwd                       # user:x:10000:10000::/home/user:/bin/ash
sudo umount $D/mnt; rmdir $D/mnt
md5sum $D/samsung-m52xq-root.img $D/samsung-m52xq-boot.img | tee $D/images.md5
```

Всё то же самое за один запуск делает скрипт `image/build-rootfs.sh`:

```sh
OUT=$D PKGS=<репо>/image/local-repo MODULES=/путь/к/lib/modules/7.1.13 \
PMB="/opt/python3.10/bin/python3.10 $PMB_DIR/pmbootstrap.py" ./image/build-rootfs.sh
```

## 9. Ловушки

1. **losetup в объединённом /usr.** В пакете устройства r6 post-install делал `ln -sf /usr/sbin/losetup /usr/bin/losetup`: костыль
   из времени, когда в edge `/usr/sbin` был отдельным каталогом. Сейчас `usr/sbin -> bin`, поэтому команда заменила настоящий файл
   ссылкой на самого себя, и mkinitfs падал:
   `unable to add "/usr/sbin/losetup": EvalSymlinks: too many links`.
   В r7 ссылка создаётся только при отсутствии файла. Уже испорченный корень лечит `apk fix losetup`.
2. **uid 12345.** Индекс и подпись пакетов pmbootstrap делает от пользователя `pmos` (uid 12345). Папки `packages` и `config_abuild`,
   созданные с хоста, отдайте ему.
3. **Основной рабочий каталог не трогать.** Там конфиг порта Plasma: `ui=plasma-mobile` и закреплённые версии KDE 6.28. Если сменить
   там `ui`, pmbootstrap пересоздаст его rootfs-chroot. Поэтому `-c` со своим конфигом и свой `work`.
4. **`build_pkgs_on_install = False`.** Иначе на «грязных» pmaports pmbootstrap может начать собирать пакеты из `temp/`.
5. **e2fsck хоста** ложно ругается на `orphan_file` (раздел 7).
6. **Пароль** задаётся только ключом `--password`, иначе install спрашивает его интерактивно.
